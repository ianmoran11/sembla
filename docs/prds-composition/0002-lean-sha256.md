# PRD 0002: Pure-Lean SHA-256, domain-separated hash records, and rule words

## Context

Read `docs/prds-composition/README.md` first; its constraints bind. DECISIONS
§J2/§J4 (PRD 0001) fix SHA-256 with domain separation as the project hash and
content-addressed `u32` rule words as the RNG identity mapping. The Lean
frontend must compute these itself — the canonical linker (PRD 0007) derives
rule words and the exporter (PRD 0005) feeds hashes — and the folder README
forbids new Lean dependencies, so SHA-256 is implemented in pure Lean here.
The Rust side already has `sha2` in `sembla-cli`; PRD 0003 adds it to
`sembla-ir` and cross-checks the shared vector fixture created here.

## Goal

A pure-Lean, test-pinned SHA-256 with domain-separated hashing, hash records,
and rule-word derivation, plus a frozen cross-language vector fixture that
Lean tests verify now and Rust tests verify in PRD 0003.

## Specification

### 1. Implement SHA-256 in `frontend/Sembla/Hash.lean`

Implement FIPS 180-4 SHA-256 over `ByteArray`:

- Message padding: append `0x80`, then zero bytes until length ≡ 56 (mod 64),
  then the original bit length as a big-endian 64-bit integer.
- Process 64-byte blocks with the standard message schedule (W[0..63]), the
  standard eight initial hash values, and the standard 64 round constants K.
  Take the constant values from FIPS 180-4 (they are widely published); do not
  invent them — the known-answer tests below will catch any transcription
  error.
- All words are `UInt32` with wrapping arithmetic; use explicit right-rotate
  (`(x >>> n) ||| (x <<< (32 - n))`) and shift helpers. Assemble/emit words
  big-endian.

Public API (namespace `Sembla.Hash`):

```lean
def sha256 (data : ByteArray) : ByteArray        -- 32 bytes
def sha256Hex (data : ByteArray) : String        -- lowercase hex, 64 chars
def sha256HexOfString (s : String) : String      -- UTF-8 bytes of s

structure HashRecord where
  algorithm : String     -- always "sha256" here
  domain : String
  digest : String        -- lowercase hex
  deriving Repr, BEq

/-- SHA-256(domain ++ 0x00 ++ payload). The single 0x00 separator byte is the
frozen domain-separation convention from DECISIONS §J2. -/
def domainDigest (domain : String) (payload : ByteArray) : ByteArray
def hashRecord (domain : String) (payload : ByteArray) : HashRecord

/-- Big-endian u32 from the first 4 bytes of
`domainDigest "sembla.rule-word/v1" identity.toUTF8`. -/
def ruleWord (identity : String) : UInt32

/-- true for 0xFFFFFFFE and 0xFFFFFFFF, the reserved sweep/prior namespaces
in crates/sembla-runtime/src/rng.rs. -/
def isReservedRuleWord (w : UInt32) : Bool
```

Write the code for compiled execution (it runs inside `sembla-export` and
`sembla-link`): use `ByteArray`/`Array UInt32` loops or folds, not `List`.

### 2. Known-answer tests in `frontend/Sembla/HashTests.lean`

Pin at least these FIPS vectors with `#guard`:

```text
sha256Hex ""    = "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
sha256Hex "abc" = "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"
sha256Hex "abcdbcdecdefdefgefghfghighijhijkijkljklmklmnlmnomnopnopq"
                = "248d6a61d20638b8e5c026930c3e6039a33ce45964ff2167f6ecedd419db06c1"
```

Also pin: a >64-byte input (e.g. 100 `'a'` characters — compute the expected
digest with `python3 -c "import hashlib; print(hashlib.sha256(b'a'*100).hexdigest())"`
and paste it), a `domainDigest` case, `isReservedRuleWord` truth table
boundaries (`0xFFFFFFFD → false`, `0xFFFFFFFE → true`, `0xFFFFFFFF → true`),
and every rule-word vector from the fixture below. Import `HashTests` from
`frontend/Sembla.lean` so `lake build` runs the guards. If `#guard` proves too
slow at elaboration for the longer vectors, keep at least the empty-string and
`"abc"` guards and move the rest into a `test` function invoked from an
imported module via `#guard` on its `Bool` result — build failure on mismatch
is the requirement, the mechanism is not.

### 3. Frozen cross-language vector fixture

Create `fixtures/hash/vectors.json` (new top-level `fixtures/` directory;
ordinary pretty-printed JSON — this file is a test input, not a canonical
artifact) with two arrays:

```json
{
  "sha256": [
    { "input": "", "hex": "e3b0..." },
    { "input": "abc", "hex": "ba78..." }
  ],
  "rule_words": [
    { "identity": "occ:population#infect", "word": 0 },
    { "identity": "occ:policy#restrict", "word": 0 },
    { "identity": "occ:north/population#infect", "word": 0 },
    { "identity": "occ:south/population#infect", "word": 0 },
    { "identity": "occ:epidemic/population#infect", "word": 0 }
  ]
}
```

Replace every `"word": 0` placeholder with the true value computed by:

```bash
python3 -c "import hashlib,sys; i=sys.argv[1]; print(int.from_bytes(hashlib.sha256(b'sembla.rule-word/v1\x00'+i.encode()).digest()[:4],'big'))" 'occ:population#infect'
```

Then duplicate the same identity/word pairs as `#guard ruleWord "..." = ...`
literals in `HashTests.lean` (Lean does not parse the fixture; the fixture
exists so PRD 0003's Rust test verifies the identical constants). The five
identities above are from the folder README's frozen worked example and must
appear verbatim. Record the python commands and outputs in the implementation
notes.

### 4. Registration

Add `import Sembla.Hash` and `import Sembla.HashTests` to
`frontend/Sembla.lean`. No lakefile change is needed (the library glob covers
new modules under `Sembla/`).

## Allowed files

- `frontend/Sembla/Hash.lean` (new)
- `frontend/Sembla/HashTests.lean` (new)
- `frontend/Sembla.lean` (imports only)
- `fixtures/hash/vectors.json` (new)
- implementation notes/artifacts created by the managed run

## Non-goals

- Any Rust change (PRD 0003 consumes the fixture).
- Streaming/incremental hashing, other algorithms, HMAC, or performance
  tuning beyond avoiding `List`-based byte handling.
- Canonical JSON, plan types, or identity construction (later PRDs).
- New Lean dependencies — the whole point is a dependency-free implementation.

## Acceptance criteria

1. `cd frontend && lake build` passes with the new modules imported, which
   means every `#guard` known-answer and rule-word vector holds.
2. `Sembla.Hash` exposes exactly the API of §1 (names may gain doc comments,
   not different signatures).
3. `fixtures/hash/vectors.json` exists, contains the five frozen identities
   with non-placeholder words, and each word equals the corresponding Lean
   `#guard` literal.
4. `isReservedRuleWord` returns true exactly for `0xFFFFFFFE` and
   `0xFFFFFFFF`, pinned by guards.
5. `./scripts/check.sh`, `bash frontend/scripts/check-parity.sh`, and
   `git diff --check` pass; `examples/` and all Rust crates are unchanged.
