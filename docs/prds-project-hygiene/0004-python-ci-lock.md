# PRD 0004: Add a hashed transitive lock for the NPE CI environment

max_review_cycles: 5

## Context

Read this folder's `README.md` first. `calibration/npe/requirements.txt` pins
seven direct packages but leaves their transitive graph and downloaded wheel
identity unresolved. CI installs it directly on Ubuntu/Python 3.12. That is
weaker than the repository's reproducibility posture and can drift without a
source edit. The existing versions and committed NPE `.pt`/CSV/diagnostic
artifacts are scientific evidence and must not be regenerated by this work.

## Goal

The Linux x86_64, Python 3.12 NPE smoke job installs a reviewed, fully
transitive requirements lock with exact versions and SHA-256 hashes, while the
direct requirements remain the human-maintained input and all scientific
artifacts remain byte-identical.

## Requirements

1. Keep `calibration/npe/requirements.txt` as the concise direct input. Preserve
   its existing scientific package versions unless resolution proves impossible;
   any version change is a blocker requiring explicit user approval, not a
   hygiene substitution.
2. Add a clearly named Linux/Python-3.12 CI lock, such as
   `calibration/npe/requirements-ci.lock`, containing the complete resolved
   graph. Every installable requirement must use `==` and one or more
   `--hash=sha256:...` entries. Preserve the CPU-only PyTorch index/source
   policy and avoid dependency-confusion-prone source ambiguity.
3. Add a deterministic lock regeneration/check script. Run it in a
   Linux/amd64 Python 3.12 container pinned by immutable image digest, pin the
   lock generator version, write through a temporary file, and fail if
   regeneration differs. Document the exact image digest, command, and platform
   contract in `calibration/npe/README.md`.
4. Update the NPE CI job to install the lock with `--require-hashes` rather than
   resolving the direct input. Do not add an unpinned bootstrap tool to normal CI.
5. Add a lightweight structural test that rejects unpinned/unhashed entries,
   unexpected indexes, editable/VCS requirements, and direct-input packages
   missing from the lock.
6. Add one container validation entry point that regenerates to a temporary
   file, byte-compares the checked lock, creates a fresh environment, installs
   with `--require-hashes`, and runs `./scripts/check-npe-smoke.sh` inside the
   pinned Linux/amd64 Python 3.12 container. Docker is available at the audited
   baseline; if this authoritative validation cannot run, implementation remains
   blocked rather than deferring approval to an untriggered CI job.
7. Do not run data generation, training-artifact regeneration, or fixture
   regeneration. Snapshot hashes for the curated NPE artifacts before and after.

## Allowed files

- `calibration/npe/requirements.txt` only if comments/input structure need
  clarification; package versions are frozen absent explicit approval
- `calibration/npe/requirements-ci.lock` (new)
- Lock generation, structural-check, and container-validation scripts under
  `calibration/npe/` or `scripts/`
- `calibration/npe/README.md`
- `calibration/npe/tests/**` for lock-structure tests
- `.github/workflows/ci.yml`
- `scripts/check-npe-smoke.sh` only if needed to consume/verify the lock
- `docs/ci.md`
- Managed implementation notes/artifacts

## Non-goals

- Upgrading NumPy, pandas, SciPy, SBI, Torch, pytest, or their scientific
  behavior.
- Regenerating any file under `calibration/npe/artifacts/`.
- Making one lock serve macOS; the existing direct input may continue to support
  local Darwin setup.
- Enabling generic pip Dependabot updates.

## Implementation notes

A generated lock may be large; review it as generated security/reproducibility
material, not hand-authored prose. Record generator version, input hash, target
platform, Python version, index policy, and regeneration command in the file
header or adjacent documentation.

## Test and check guidance

Before editing, record:

```bash
git ls-files calibration/npe/artifacts | sort | xargs shasum -a 256
```

Run the structural tests and the container validation entry point. It must use
`docker run --platform linux/amd64` (or the equivalent pinned-container command),
regenerate and compare the lock, install it with `--require-hashes`, and execute
`./scripts/check-npe-smoke.sh`. A host-platform mismatch is not a waiver because
the pinned container is the acceptance environment. Also run the
repository/parity/diff checks from the folder README.

## Acceptance criteria

1. The CI lock is complete, exact, hashed, deterministically regenerable, and
   mechanically checked against the direct requirements.
2. CI installs with `--require-hashes` on Python 3.12 and no normal CI step
   performs unconstrained transitive resolution.
3. The pinned Linux/amd64 Python 3.12 container regenerates the lock
   byte-identically, installs it from scratch with `--require-hashes`, and passes
   the full reduced NPE smoke check before review approval.
4. Every tracked file under `calibration/npe/artifacts/` retains its pre-PRD
   SHA-256 hash.
5. Rust/Lean repository checks and `git diff --check` pass; no unrelated lock or
   fixture changes occur.
