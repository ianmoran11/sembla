# PRD 0004 implementation — attempt 1

## Scope

Implemented the Linux/amd64 CPython 3.12 NPE CI lock only. No scientific package
version, NPE data, training output, fixture, Cargo lock, simulation surface, or
Lean surface was changed or regenerated.

## Lock contract

- Preserved all seven direct requirement lines and versions in
  `calibration/npe/requirements.txt`.
- Replaced the ambiguous PyTorch extra index with the PyPI index plus the
  torch-only CPU `--find-links` page.
- Added a 120-package, exact, fully SHA-256-hashed
  `calibration/npe/requirements-ci.lock`.
- Lock SHA-256: `449deac8b60acd666607341394f0e21ed3f8a00f67bc5c9fbca3473ae1c5f8d0`.
- Target image:
  `python:3.12.8-slim-bookworm@sha256:8859bd6ca943079262c27e38b7119cdacede77c463139a15651dd340087a6cc9`
  with `docker run --platform linux/amd64`.
- Generator: `uv==0.5.18`, bootstrapped from its exact Linux wheel hash
  `04e6c62d8947f62f1ec3255b5743cc775950b6203b06bf9c4d50682dcd68f340`.
- Resolution cutoff: `2026-07-23T00:00:00Z`.
- The generator writes through a temporary file and records the direct-input
  hash, target, image, generator, cutoff, source policy, and build prerequisites
  in the lock header.
- `uv` 0.5.18 omits hashes for flat-link artifacts. The generator strictly
  requires the single `torch==2.5.1+cpu` result and attaches the independently
  verified Linux CPython 3.12 wheel hash
  `4856f9d6925121d13c2df07aa7580b767f449dfe71ae5acde9c27535d5da4840`.

`nflows==0.14` is sdist-only. To prevent pip from creating an unconstrained
PEP-517 build environment, the lock includes `setuptools==75.8.0` and
`wheel==0.45.1`. The installer first installs those exact hashed blocks without
dependencies, then installs the full lock with both `--require-hashes` and
`--no-build-isolation`. The authoritative container check also rejects any
`Installing build dependencies` output.

## CI and validation

- CI now pins Python `3.12.8`, keys its pip cache from the CI lock, and invokes
  `calibration/npe/install-requirements-ci.sh`; normal CI does not install the
  generator or resolve `requirements.txt`.
- Added structural mutation tests for unpinned/unhashed entries, source policy,
  editable/VCS syntax, missing direct inputs, CPU Torch identity/hash, build
  tools, immutable metadata, and CUDA-package rejection.
- Added `./scripts/check-npe-lock.sh` as the single authoritative entry point.
  It mounts the repository read-only, regenerates to a temporary file,
  byte-compares the lock, creates a fresh virtual environment, performs the
  hashed installation without build isolation, and runs the reduced NPE smoke.
